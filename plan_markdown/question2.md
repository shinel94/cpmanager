1. 코드 진행의 최대 길이 -&gt; 모든 추천은 코드 4개 단위의 진행으로만 제한, 이때 4마디 이상의 코드 진행이 있는 경우, 4의 배수단위로 끊어서 진행만 추천 (ex, 8마디 진행인 경우 1\~4번째 코드 진행, 5\~8번째 코드 진행을 따로따로 추천, 이외에 4마디 단위가 아닌 경우 (9마디인 경우 9번째 마디에 해당) 남는 단위의 마디는 추천 제외,

2. 사용 가능한 도수 범위 -&gt; 설정할 수 있는 모든 코드를 설정할 수 있어야 함, 하지만 전형적인 코드가 먼저 사용자가 선택할 수 있도록 기능 제공

3. 추천 결과의 개수와 정렬 기준 -&gt; 추천 갯수는 UI크기에 맞게 제안해주나 기본적으로는 3개를 추천하고 페이지네이션으로 다음 추천을 확인할수있도록 기능 제공, 또한 사용자가 추천 기준을 무작위, 대중성 우선, 코드 연결성 우선, 다양성 우선로 선택할수있고 db상에 미리 해당 정렬 기준과 관련된 데이터가 저장되어서 검색에 활용할수있어야함

4. “모든 코드 설정”의 범위 -&gt; 조성을 기준으로 diatonic 코드 표가 먼저 나타나고, 특정 도수를 선택한뒤에 해당 코드의 텐션여부나 다른 코드 여불르 설정 (ex: cmajor조성인 경우, C Dm Em F G Am Bdim 이 먼저 보이고, Dm를 눌렀을때 텐션이나 마이너 메이저를 변경할수있는 UI가 나타나고, 해당 코드를 선택했을때 어떤 진행인지 다음코드를 가지고 기법을 확인해서 알려줌)

5. 장조 지원과 모달 인터체인지의 관계

- 장조만 지원이라는 것의 의미는 곡자체를 생성할때 1도의 기준을 설정하는 것으로 장조만 지원한다는 의미, Aminor조성을 쓰고자 한다면 Cmajor조성으로 곡 설정하여 작곡하는 형태, 코드 선택의 경우에는 모든 코드가 선택되어야함

6. 기법 판별의 적용 범위 -&gt; 한마디에 코드가 여러개 있는 경우에는 현재는 해당 마디, 해당 마디와 관계가 있는 마디에는 분석을 진행하지 않으며, 코드 진행의 경우에는 최대 4마디를 기준으로 분석을 하게 되고, 변경하는 코드가 다음 코드와 진행이 어떻게 되는지 그리고 이전 마디와 어떻게 흘러가는지 확인할 수 있게 되나 4마디를 넘어서는 경우 prechorus 의 4번째 마디와 5번째 마디 사이에는 분석을 진행하지 않음)

7. 기법이 중복될 때의 우선순위

- DB에 우선순위와 관련된 기준이 저장될 예정이며 해당 priority를 기준으로 결과 제공

8. 송폼 구간별 추천 방식

- 송폼 구간에서 4마디 기준으로 진행을 추천하고, 이때 특성 송폼에 4마디 모두 코드가 할당된 경우에는 추천을 제공하지 않음

- 구간에 이미 코드가 일부 입력되어 있을 때 기존 코드를 유지했을때의 진행을 추천해주어야 하며, 목록에 없는경우 추천 없음으로 사용자가 나머지를 직접 설정

9. 앞뒤 코드 입력의 의미 -&gt; 앞뒤 코드라는건 마디를 기준으로 코드고 기본적으로 4마디를 기준으로 진행을 선택하면 모든 코드가 설정되어 있고, 해당 코드를 기준으로 앞코드나 뒤 코드가 적용됨

10. 프로젝트 저장 형식

- 모든 데이터는 sqlite에 테이블을 적절히 만들어 데이터로 저장

- 자동 저장과 기존 프로젝트 불러오기는 초기 기능에 불필요

11. 로컬 프로그램의 배포 방식

- 노드가 설치된 PC에서 부트 스트랩을 자바스크립트 파일을 실행하여, 최초 프로그램이 설치되도록 기능 제공하는 것이 목적이나, 지금은 프로젝트를 내려받아 실행하는 개발자용 구조로 진행

12. 데이터베이스 수정 권한

- 코드 진행 데이터베이스는 최초 제공하고, 사용자가 필요한 경우 임의로 진행 데이터를 추가할 수 있어야 함 이때 한마디에 코드가 여러개인경우에는 현시점에서는 저장 및 불러오기 기능 제공하지 않음

13. UI 결정 시점

- 기능이 대략적으로 확정된 뒤 UI 시안 결정

14. 사업 제안서의 성과 기준

- 현재 성공 기준은 기능 중심입니다.
