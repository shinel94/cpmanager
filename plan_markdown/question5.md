1. 사용자 진행 검색 방식

예시를 보면 저장된 진행이 다음과 같을 때:

I - ii - I - I

검색 결과는 다음처럼 동작합니다.

- I - ii → 검색됨

- I - ii - I → 검색됨

- I - I → 검색되지 않음

- I - ii - ii → 검색되지 않음

검색은 4마디 기준으로 검색이 되어야함 1M -2m - 1M - 1M 진행인 경우에 x - 2m - 1M - x 형태로 검색하거나 1M - 2m - x - x형태로 검색이  되는 형태, 검색역시 4마디를 기준으로 검색되어야함

2. 진행 검색 기준 -&gt; 내부에 저장된 데이터는 모두 도수를 기준으로 저장되고, 사용자가 진행할때는 곡에 조성에 맞는 코드로 변환되어서 확인되어야함, 내부적으로 해당 코드를 도수로 변환하는 작업을 거쳐서 추천 및 저장이 진행

3. 사용자 진행 저장 항목

사용자 추가 진행을 저장할 때 최소한 다음 정보가 필요합니다.

- 진행 이름

- 4개 코드 또는 도수 (저장시에는 도수만 입력)

- 자주 사용된 송폼 (복수 선택 가능)

- 설명 또는 메모

- 등록일

이 중 어떤 정보를 입력받을지 정해야 합니다. -&gt; 등록일을 제외한 정보를 입력

4. 저장·불러오기 UI

수동 저장·불러오기를 지원하므로 다음 동작이 필요합니다. 모든 동작 기능 제공

- 새 곡 만들기

- 곡 이름 지정

- 저장

- 저장된 곡 목록 보기

- 곡 불러오기

- 곡 삭제

5. 코드 변형의 초기 범위

“전형적인 코드를 우선 제공”하는 방향은 정해졌지만, 초기 버전에 포함할 기본 목록은 필요합니다.

예를 들어 다음 정도를 1차 범위로 정할 수 있습니다. 아래로 범위 확정

- 기본 코드: 장조, 단조, 디미니시드

- 7th 코드: maj7, 7, m7

- 확장 코드: 9

- 차용화음: 대표적인 모달 인터체인지

- 베이스 변형: 슬래시 코드
