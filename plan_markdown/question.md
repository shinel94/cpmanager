1. 대상 사용자와 목적

1. 주요 사용자는 누구인가요? 작곡 입문자 및 음악 및 작곡을 취미로 즐기는 자

2. 핵심 목적은 무엇인가요? 코드 진행을 쉽게 만드는 보조 도구로서, 진행을 어떻게 구성해야하거나 매번 같은 진행만 하게 되는 사람들에게 도움되는 도구

2. 코드 진행 추천 기준 개발 시점에 미리 가능한 모든 조합을 만들어 둔뒤에 사용자가 1도를 입력했을때 1도 로 시작하는 모든 조합들중 몇가지를 추천, 추천 기준은 임의로 진행하고 목록을 검색할 수 있도록 제공

3. 사용자가 입력하는 정보는 어디까지인가요?

- 전체 노래 구성의 송폼 및 송펌 별 길이 설정 (ex: intro 8bar - verse 8bar - prechorus 4bar - chorus 8bar - interlude 4bar - verse 8bar - prechorus 4bar - chorus 8bar - bridge 4bar - chorus 4bar - outro 4bar)

- 조성 선택 (C major, D minor)

- 송폼 별 도수 입력

- 앞뒤 코드 입력

4. 1도 - 2도 - 4도 - 5도는 단순한 도수 진행인가요, 아니면 각 도수에 해당하는 다이어토닉 코드까지 자동 변환하는 것인가요? 진행 추천은 1도 2도 4도 5도 형태로 추천해주고 선택한 뒤에는 실제 조성에 맞는 코드로 변환되어서 작성되어야 하고, UI상으로 송폼별로 어떤 코드 진행인지 확인 가능

5. 장조뿐 아니라 단조도 지원하나요? 지금 시점에는 장조만 지원

6. 다음 코드 유형도 초기 버전에 포함하나요? 사용자가 특정 부분에 모든 코드를 설정할 수 있어야 함, 그때 설정된 코드가 어떤 기법을 적용하였는지도 확인할 수 있어야 함

- 7th, 9th 등 텐션 코드

- 세컨더리 도미넌트

- 모달 인터체인지

- 디미니시드 코드

- 슬래시 코드

7. 추천 데이터베이스는 직접 정리한 규칙 기반 데이터인가요, 아니면 AI 또는 통계 기반 추천까지 고려하나요? 지금 시점에는 정리된 데이터를 기반으로 한 규칙으로 한정

8. 사용자가 진행을 수정했을 때 기법을 자동 판별하는 것인가요? 정해진 규칙에 맞는기법이 있다면 해당 기법이 적용된 진행이다라는 것을 확인할 수 있어야 함 (중복될 경우 한가지 조금더 대중적인 기법으로 적용, 대중적인것이 불명확한경우 임의의 기법으로 알려주어도 무방)

- 예: C - F - G에서 C - Fm - G로 바꾸면 모달 인터체인지로 표시

- 아니면 적용 가능한 기법 목록만 제안 -&gt; 특정 코드 변경 전에 UI상으로 이 코드로 변경하면 어떤 기법이 적용된다는 것을 확인할 수 있어야함

9. 송폼의 범위는 어디까지인가요?

- Verse, Pre-Chorus, Chorus, Bridge, Intro, Outro

- 사용자가 직접 구간명을 입력할 수 있는 구조이고 금번에 순서에 제약을 두지 않음 (intro - outro - verse - intro -outro 형태도 가능)

10. “프리코러스에서 2도를 입력”한다는 것은 무엇을 의미하나요?

- 프리코러스 구간에 사용자가 선택한 부분에  2도 코드를 배치 -&gt; 2도가 배치된 이후에 해당 위치에 2도가 나오는 코드 진행을 추천, 특정 송폼에 모든 코드가 들어있는 경우에는 코드 진행을 추천하지 않고, 코드를 변경했을떄 어떤 기법이 적용되는지 확인하는 UI제공

11. 기본 1마디 1코드 외에 다음 기능도 필요한가요?

- 현시점에서는 4/4박자만 지원, 마디 안에서 코드가 여러개가 들어가는 경우에는 적용하는 기법이나 어떤 진행인지는 확인 할수 없어도 됨, 1박마다 코드 1개를 설정할 수 있음

- 송폼 단위로 마디 길이를 설정가능

12. 사용자가 편집하는 화면은 타임라인 방식인가요, 악보·코드 차트 방식인가요? 지금은 악보 코드 차트 방식일것같은데, 추후에 확정하면됨 지금 시정에서는 정하지 않고 진행

4. 로컬 브라우저 프로그램의 범위

13. “로컬 프로그램”은 다음 중 어느 형태인가요?

- 로컬에서 프로젝트를 내려받아 실행하고 localhost로 접속하고, 해당 프로그램에서 로컬의 db에 접속해서 작곡을 진행하는 프로그램

14. 프로젝트 저장은 어디에 하나요?

- 사용자의 컴퓨터 파일 시스템

15. 회원가입과 서버 기능은 초기 범위에서 제외하나요? -&gt; 로컬에서 작동하는 프로그램이기 때문에 회원보다 사용자의 느낌으로 인증이 없는 유저기반의 서비스

16. MIDI 재생은 후속 기능이라고 되어 있는데, 사업 제안서에는 장기 로드맵으로 포함할까요? 포함

17. MIDI 기능은 무엇을 의미하나요?

- 브라우저에서 프로그램내 기본으로 제공하는 midi파일 기준 코드 소리 재생

18. 코드 진행을 PDF, 이미지, MIDI 등으로 내보내는 기능도 필요한가요? 지금 시점에서는 불필요

6. 사업 제안서에 필요한 내용

19. 기존 도구와 비교했을 때 가장 큰 차별점은 무엇인가요?

- 송폼 기반 추천을 통해서 작곡을 보다 빠르게 할 수 있고, 특정 코드를 수정하고자 할때, 수정도 보다 용이하게 할 수 있도록 도와주는 도구

20. 사업 제안서의 제출 대상은 누구인가요?

- 내부 개발 승인

21. 수익 모델을 고려하고 있나요?

- 무료 데스크톱 앱 기반으로 개발 후, 추후 기능이 완료된 이후에 프로그램 단위의 판매 또는 후원으로 서비스 운영

22. 1차 버전의 성공 기준은 무엇인가요?

- 코드 진행 데이터베이스 구축 및 추천부터 곡 저장까지 가능한 작동 제품
