1. 4마디와 4코드의 관계

- 기본적으로 1마디에 코드 1개일 때만 4마디·4코드 추천인가요? -&gt; 정확함

- 1마디에 여러 코드를 입력한 경우에는 추천과 기법 분석을 모두 제외하는 것으로 확정하면 될까요? -&gt; 정확함

- 2마디 또는 3마디 구간은 추천하지 않고, 5\~7마디 구간은 앞의 4마디만 추천하는 것인지도 정해야 합니다. (8마디 진행의 경우 1\~4마디 기준, 5\~8번째 기준으로만 추천 진행, 3\~6마디 기준으로는 추천 진행하지 않음, 특정 송폼의 마디가 7마디 인경우에 처음 1\~4번째마디에만 추천 5\~7번째 마디는 추천없음)

2. 코드 진행 추천의 고정 범위

- 사용자가 직접 추가하는 진행도 반드시 4마디·4코드 단위인가요? -&gt; 현시점에서는 반드시 4마디 4코드

- 4마디보다 긴 진행을 저장할 수는 있지만 추천할 때만 4마디 단위로 분리하나요? -&gt; 정확함

3. 곡 저장 기능의 충돌

- [question.md](http://question.md)에서는 MVP 목표에 “곡 저장”이 포함되어 있습니다.

- [question2.md](http://question2.md)에서는 자동 저장과 기존 프로젝트 불러오기가 초기 기능에서 제외되어 있습니다.

- 따라서 초기 버전에서 다음 중 하나를 선택해야 합니다.

- 수동 저장·불러오기는 지원 -&gt; 저장이라함은 특정 사용자가 본인의 노래를 제공하는 UI로 편집 하는것으로 한하여 db에만 데이터가 저장되고 별도로 pdf기반의 악보로 제공할 필요는 없음)

- 현재 작업 중인 데이터만 SQLite에 임시 저장

- PDF로 악보를 저장하거나 midi 재생 결과를 저장하는 기능은  MVP 이후로 제외

4. SQLite의 역할

- 추천 진행 데이터베이스와 사용자가 작성한 곡 데이터를 하나의 SQLite에 저장하나요? 하나의 데이터베이스로 제공하고 테이블로 구분

5. 기법 판별의 기준

- 기법 판별은 항상 4마디 범위 안에서만 수행하나요? 정확함

- 예를 들어 4마디의 마지막 코드와 다음 4마디의 첫 코드 사이에는 분석하지 않는 것으로 확정하면 될까요? 정확함

- 한 마디에 코드가 여러 개인 경우에는 해당 마디만 제외하고 나머지 마디는 분석하나요, 아니면 해당 마디만 제외

6. “모든 코드”의 범위

- 사용자가 선택할 수 있는 코드의 범위를 정의해야 합니다.

- 예: C, Dm, G7, Cmaj7, Fm, G/B, Bdim

- UI로 C를 선택했을때 C에서 파생되는 모든 코드를 선택할수있어야함, (ex: C, Cm, Cdim, Cm(b5), Cmaj7, C9, C7 등)

7. 추천 정렬 기준의 데이터 출처

- 대중성 기준은 어떤 데이터로 결정하나요? -&gt; 데이터 베이스에 저장된 기준으로 내부에서 수작업으로 별도의 기준을 설정예정

- “무작위”도 완전한 무작위인지, 조건에 맞는 진행을 섞어서 보여주는 방식인지 정해야 합니다. -&gt; 조건에 맞는 것들 중 무작위로 먼저 추천

8. 사용자 추가 데이터의 범위

- 사용자가 추가할 수 있는 것은 4마디·4코드 진행만인가요? 정확함

- 추가한 진행에 대중성·연결성·다양성 등의 분류값도 사용자가 직접 입력하나요? 입력하지 않고 별도로 내가 저장한 코드 진행을 따로 검색할 수 있어야 하며 일반적인 추천해는 나오지 않음

9. 10분 목표의 측정 시작점

- 10분은 빈 프로젝트를 기준으로, 작곡 입문자가 사용방법에 대해서 설명을 들은 이후에 전형적인 송폼을 기준으로 첫번째부터 마지막 코드까지 설정을 완료하는 것을 기준

10. 배포 범위

- 현재는 개발자용 실행 구조로 진행하되, 사업 제안서에는 향후 설치형 데스크톱 앱으로 전환한다고 작성하면 될까요? 정확함

- 최종 사용자는 Node.js를 설치하지 않아도 되는 형태를 목표로 하나요? 아님 노드는 사용자가 임의로 설치하는 것으로 가정
