1. 진행 검색 규칙

I - ii - I - I를 기준으로 다음과 같은 검색을 지원하는 것으로 이해됩니다.

- x - ii - I - x → 검색

- I - ii - x - x → 검색

- I - I - x - x → 검색되지 않음

즉, 정확히 4개의 위치를 가지며 x는 와일드카드로 사용하는 방식입니다. 다음 내용을 확정해야 합니다.

- x가 어느 위치에나 사용 가능한가요? -&gt; 가능

- x - x - I - I도 검색 가능한가요? -&gt; 가능

- 검색 결과는 해당 4마디를 포함한 진행만 보여주나요? -&gt; 맞음

- 실제 코드가 아니라 도수 패턴만 비교하는 것이 맞나요? -&gt; 맞음  
추가로 모두 x인 경우에는 검색을 진행하지 않음

2. 도수만 저장하는 문제

현재는 내부 데이터를 도수 기준으로 저장한다고 되어 있지만, 도수만으로는 코드의 세부 정보를 모두 표현하기 어렵습니다.

예를 들어 다음은 모두 다른 코드입니다.

- I

- Imaj7

- I7

- ii

- ii7

- V7

- bVI

- V/G

따라서 내부 저장값은 단순히 I, ii, V만 저장하기보다는 다음과 같이 구성해야 합니다.

도수: V

코드 유형: dominant 7

확장: 없음

베이스: 기본음

또는 간단히 다음처럼 표현할 수 있습니다.

V7

이 부분은 기획서에서 도수 기반 저장이지만 코드 품질·텐션·베이스 정보를 함께 보존한다고 정의해서 진행
