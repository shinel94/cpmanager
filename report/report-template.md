## 부록: 템플릿 사용 규칙

### 파일 명명 규칙

```
report/MMDD-[리뷰-주제]-report.md
```

**예시**:
- `report/0923-test-review-report.md`
- `report/0924-api-security-report.md`
- `report/0925-fe-performance-report.md`

### 심각도 기준

| 라벨 | 의미 | 대응 시점 |
|------|------|----------|
| 🔴 Critical | 시스템 동작 또는 개발 흐름에 직접적 영향 | 즉시 |
| 🟡 Warning | 기술 부채 또는 혼란 유발 | 다음 스프린트 |
| 🟢 Info | 개선하면 좋으나 운영에 문제 없음 | 백로그 |
| ✅ Positive | 잘 되어 있는 부분 (유지 필요) | 변경 시 주의 |

### 작성 원칙

1. **근거 기반 (Evidence-based)**: 모든 발견 사항에는 파일 경로, 코드 예시, 실행 결과 등 구체적 근거를 포함합니다.
2. **양면 평가 (Balanced)**: 문제점뿐 아니라 잘 되어 있는 부분(✅ Positive)도 반드시 기록합니다.
3. **실행 가능 (Actionable)**: 각 이슈에 대해 구체적인 조치 방안과 예상 소요 시간을 제시합니다.
4. **우선순위 명확 (Prioritized)**: 모든 개선 항목에 P0~P3 우선순위를 부여합니다.
5. **Gate 기반 검증 (Gated)**: 각 단계의 완료 기준을 명시하여 완료 여부를 객관적으로 판단할 수 있게 합니다.
